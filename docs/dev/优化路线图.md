## 2 排序原则

1. **先可复现**：测试基线不修，后面的“完成”都不可验证。
2. **先已上线正确性**：BS-08 的统计口径与前端体积、FR-02/03/05/10 的验收缺口优先于新功能。
3. **先 P0 运维**：OPS 的备份、恢复、防呆、迁移手册先于 P1/P2 功能。
4. **一需求一分支**：同一批次内按 FR/BS/OPS 编号拆分支，不把多个需求混在一个 PR。
5. **可裁剪**：答辩时间不足时先保“可演示 + 可恢复 + 可解释”，通知、字段级修订、管理端 UI 可后置。

4. 更新对应 FR/BS/OPS 状态、证据、缺口与本文件状态；
5. 需求 md → docx 重建，`docs/README.md` 同步；
6. PR 写明关联的 FR/BS/OPS 与 TC 编号。
