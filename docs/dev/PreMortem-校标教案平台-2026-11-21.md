## 0 一句话结论

平台端**功能是通的**（注册→建任务→取任务包→导入契约包→审查→导出 DOCX 全链路 13/13 通过），但存在两处会让现场"讲不下去"的断点：**重复建课会把教师踢进 403 页**，以及**平台自己产不出教案**——后者不是缺陷而是设计边界，却是最可能在评审席被问倒的一句话，必须在 v2.1 用一条降级路径补上。

## 1 失败剧本（假定两周后发生）

> 评审现场：教师照流程新建任务，发现同一课题已被同事建过，点"创建"后整页变成「没有访问权限 / 越权访问已记录」，评委问"这是报错还是我没权限？"；换账号演示"生成教案"，却发现必须先装 Agent、由插件打包、再导回，平台内没有任何一个按钮能产出教案正文，评委追问"所以这个平台只是一个校验器？"

这两句话就是本清单要提前拆掉的雷。

## 2 Tigers（真问题，按证据确认为风险）

### T1 重复建课 → 403 整页（阻断）

- **证据**：E2E 第 4 步实测 `POST /api/v1/tasks` 返回 `403 {"code":"FORBIDDEN","message":"该任务属于其他教师，不能覆盖"}`，页面跳到 `/403`「越权访问已记录」。
- **根因**：`task_service.py:40-50` 把"任务身份被他人占用"建模成权限错误，并且先写一条 `authz.denied` 越权审计；`TasksView.vue:91-101` 的 `handleError()` 把任何 403 都 `router.replace('/403')`，短路掉对话框内的 `formError`。
- **为什么阻断**：教研组共教同一门课/同一班级是常态，"撞车"不是异常路径而是日常路径；一旦发生，教师丢失已填内容且被指为"越权"。
- **等级**：Launch-Blocking。

### T2 越权审计被日常操作污染（快跟）

- **证据**：同 T1 的代码路径——`authz.denied` 在业务冲突时也会落库。
- **为什么是 Tiger**：BS-06 的验收口径是"写操作留痕 100%"，审计台账里混入非越权事件会直接削弱论文里"证据链可追溯"的论证力度；评审若抽查审计日志，一条"重复建课=越权"就够解释半天。
- **等级**：Fast-Follow（与 T1 同批修，成本几乎为零）。

### T3 平台内没有"从任务到教案"的直通路径（阻断，产品级）

- **证据**：平台侧只有 `engine.draft_plan()` 给任务包塞一具校标骨架（`task_service.py:283`），`POST /api/v1/plans/import` 只收"教案 + 审查报告 + manifest"完整契约包；UI 上没有任何入口把 `plan.json` 骨架落成平台内的一版教案。E2E 第 5–6 步验证的正是这条"出平台再回来"的路。
- **为什么阻断**：答辩/试讲现场若 Agent 不可用（宿主没装、额度用尽、网络受限），演示就只能停在"任务下载成功"，讲不出"教案长什么样、八步流程怎么闭环"。这不是实现遗漏，是职责边界没补齐降级方案。
- **等级**：Launch-Blocking。

### T4 导出页只能手填版本 ID（快跟）

- **证据**：E2E 第 10 步只能从审查中心点「导出」带入 `planVersionId`；`ExportsView.vue` 的 `loadCandidates()` 只调统计接口并提示"去统计页下钻"，不提供可选版本。BS-07 已因此从 ✅ 降为 🟡。
- **为什么是 Tiger**：批量导出是 BS-07 的核心卖点（"50 份 ≤5 分钟"），没有候选清单，"批量"实际靠手工抄 ID。
- **等级**：Fast-Follow。

### T5 角色矩阵只有教师被自动化覆盖（快跟）

- **证据**：E2E 仅覆盖 teacher 角色；lead（本组可见/可推进）、admin（用户、备份、删除审批）无自动化脚本。
- **为什么是 Tiger**：BS-05 的验收口径是"越权 0"，现场最容易被要求演示的恰恰是"换个角色界面不一样"。没有脚本兜底，改一处路由守卫就可能悄悄放开权限。
- **等级**：Fast-Follow（补一条 role-matrix 脚本即可）。

## 3 Paper Tigers（担心过，但不是真风险）

| 担心 | 为什么不是风险 |
|---|---|
| DOCX 导出慢、要等 LibreOffice | 实测导出同步完成（提交→可下载 <1s），产物 5831 字节含学校/编号/授课日期/页脚版本，无需额外服务 |
| 50MB 契约包上传会拖垮平台 | 教师真实包 <5MB；`LPP_MAX_PACKAGE_BYTES` 已有硬上限与 422 拒绝 |
| 版本不可物理删除，测试数据清不掉 | 这是触发器强制的设计（`plan_version is immutable`、`audit_log` append-only），答辩时是加分项；清理只需软删除 + 停用账号 |
| 3D 结构剖面在低配机器卡顿 | E2E 里结构剖面就绪 <1s；`reduced-motion` 与"简化"视图都在 |
| 前端 console 401 会吓到教师 | 仅出现在退出登录瞬间（偶发），教师侧无可见错误提示 |

## 4 Elephants（没人明说、但在现场会被戳穿）

1. **"教师要真的走三步吗？"**：建任务 → 下载任务包 → 丢给 Agent → 导回契约包，是四个动作跨两个工具。教师如果觉得比直接开 Word 麻烦，平台就会被绕过。→ 建议在 1 次真实试讲里记录"完成一份教案的总点击/总耗时"，用数据回答而不是用设计文档回答。
2. **9 个指标里有 3 个可能永远是空的**：专家评分、SUS、平台可用性依赖人工导入，开题表 2 承诺了但没人填。→ 明确"演示时展示哪 6 个真实指标"，其余标注为"待采集"，比现场被问"这个 0 是什么意思"好。
3. **"校标"的依据文件没有正式出处**：样例是 7 份 `.doc`（`测试样例/`），没有学校下发的模板文件或授权说明。→ 答辩材料里补一句模板来源（哪位教研组长提供、哪次活动），或把"校标"改称"校本样例结构"。
4. **双端版本漂移**：换机/重装后 `engineVersion`/`templateVersion` 与库里版本不一致，导入会 422。→ v2.1 把 `doctor.py` 的版本比对放进演示前检查清单。

## 5 行动清单（Launch-Blocking 详表）

| 编号 | 风险 | 对策（最小改动） | 责任 | 截止 |
|---|---|---|---|---|
| T1 | 重复建课 → 403 整页 | 后端：他人占用返回 `409 TASK_TAKEN_BY_OTHER`（`details` 带已有 `taskId`/占用者），不再写 `authz.denied`；本人重复返回 `409 TASK_ALREADY_EXISTS`，`createTask` 支持 `confirm=true`。前端：403 只在真正的权限码时跳 `/403`，冲突留在对话框内联提示，并给「确认覆盖已有任务」按钮，保留用户输入 | 后端 + 前端 | 2026-12-05 |
| T3 | 平台内产不出教案 | 新增 `POST /api/v1/tasks/{id}/draft`：用 `engine.draft_plan()` 生成 v1 草稿并落库，状态标 `draft`、审查状态标「未审查」；任务列表与详情给「生成草稿教案」按钮。契约不新增字段，只是把骨架从任务包搬进 `plan_version`；后续 Agent 交付仍以完整契约包覆盖为新版本 | 后端 + 前端 | 2026-12-12 |
| T4 | 导出页无候选版本 | 导出页加候选列表（课题/周次/版本号/审查结论，仅列已通过，勾选即导出），手填 ID 保留为高级入口 | 前端 | 2026-12-12 |

**快跟（30 天内）**：T2（与 T1 同批，删掉冲突路径的越权审计）、T5（补 role-matrix E2E：lead 只读+推进、admin 用户/备份/删除审批）、UI-12 的 toast 队列清理与筛选栏安全区（E2E 第 11 步截图）、UI-04 的登录页开发账号提示改为读 `/api/v1/meta`。

**观察（不排期）**：退出登录瞬间的 401 竞态（偶发，无教师可见影响）、3D 剖面在 4K 屏的首帧、通知中心在数据量 >50 条时的分页。

## 6 复验方式（怎么证明修好了）

1. 现有教师端脚本必须回归全绿：`cd src/frontend && npm run e2e:teacher`（13/13）。
2. T1 的验收要加一步负例：以 A 教师建任务、B 教师建同身份任务 → 断言对话框仍在、提示含 `TASK_TAKEN_BY_OTHER` 与占用者、URL 不变成 `/403`、审计表无 `authz.denied`。
3. T3 的验收：无 Agent 环境下，任务详情点「生成草稿教案」→ 教案库出现该课题 `v1`、状态「未审查」、正文页可渲染八步骨架、可走审查与导出流程（导出需先有审查报告，或明确降级为"仅内部预览"）。
4. T4 的验收：导出页候选列表勾选 2 份 → 创建导出 → 两条都 succeeded 且可下载。
5. T5 的验收：`e2e-role-matrix.mjs` 三账号各跑一遍，越权页应只出现在真实越权操作上。

## 8 下一版范围建议（v2.1）

**只做三件事**：T1（含 T2）、T3、T4；配套补 T5 的 role-matrix 脚本与两条 UI 缺口。其余（专家评分采集、审计日志可视化、性能压测）留到 v2.2——答辩前每多一个功能，就多一个现场失败面。

**明确的取舍**：v2.1 不引入任何新的外部依赖（不装队列、不装对象存储、不换 ORM），T3 也只复用已有 `engine.draft_plan()`，保证换机后一条命令还能跑起来。
