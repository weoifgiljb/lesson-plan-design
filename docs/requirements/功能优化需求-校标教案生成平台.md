## 摘要

**一句话**：主链路已经能跑通，但"校标合规"目前仍可被绕过，审查证据也无法复核；本轮优化要把门禁从"能跑"变成"可信"。

**最该先修的五个问题（P0）**

- 结构化写法跳过"必须完成/必做"，活动分钟合计与计划学时对不上（FR-01）。
- 只含轻微问题、尚未闭环的报告仍能导出（FR-03）。
- 审查报告不存被审教案，轮次可回退，同一份教案可反复"通过"（FR-05）。
- MCP 一次坏参数就让服务退出（FR-07）。
- 中文 Windows 下 hook 在校验失败时解码崩溃，命令在 `python` 与 `py -3` 之间漂移（FR-08）。

**预期结果**：结构合规率 ≥95%，门禁误放行 0，证据链完整率 100%，跨宿主冒烟 5/5，导出一次成功率 ≥90%；教师单份耗时较人工下降 ≥30%（探索性）。

**交付节奏**：P0 在 2026.12 完成，P1 在 2027.02 前完成，P2 按 2027.03 收尾，P2 可裁剪。

**阅读指引**：只看结论读本节；要排期看第 3、7 节；要写测试看第 4、6 节与附录 A。

## 1 文档说明

### 1.1 编写目的

现有原型已经跑通"草稿 → 结构校验 → 对抗审校 → 教师放行 → Word 导出"的主链路，但**能跑通不等于可验收**。本说明书从产品体验和功能测试两个视角，把仓库中已经复现的缺陷转成 18 条可判定的功能优化需求，说明每条需求解决什么问题、改到什么程度算完成、用什么用例证明它完成。

文档同时服务于三个用途：作为迭代排期的输入；作为测试设计与回归清单的依据；作为毕业论文"需求分析"与"系统测试"章节的素材。所有"现状"均来自对当前代码与产物的只读核查，复现方式见附录 A。

### 1.2 适用范围与边界

覆盖范围：插件契约层（校验、审查、门禁、导出、MCP、hooks）、知识资产（样例库、目录、模板）与测试体系。优化目标是把"校标规范"变成不漏检、可复核、跨宿主稳定的机器约束。

不在范围内：大模型生成质量本身（文风、教学法优劣）；校标 Word 版式的整体重做；与学校教务系统的对接；学生个人信息处理。对模型输出质量的判断仍由独立审校与教师负责。

口径说明：仓库中另有一份以"双端平台"为题的开题报告口径，把系统拆成插件端与平台端。本说明书以**插件/技能端的现有实现**为基线；平台端的教案库、样例库、审查记录、导出中心与统计不在本轮范围，另列 v1.1 扩展。两端共用的教案 JSON、审查报告与哈希契约仍适用于本文档。

### 1.3 现状一句话

教师用起来"能出活"，但质量门禁有可绕过的缝：结构化写法能跳过校标硬规则，旧审查证据无法复核，中文 Windows 下 hook 与 MCP 两条自动化路径都会崩，导出的 Word 还缺学校、编号与授课日期。这些不是体验问题，而是"证据链是否成立"的问题。

## 2 现状评估

### 2.1 产品定位与目标用户

平台把教案写作拆成"模型起草 + 脚本判定 + 独立审校 + 教师放行"，定位是**把校标从教师记忆变成可机检、可追溯的质量流程**，而不是替教师写教案。目标用户有三类：任课教师（要快、要合规、要能交）、教研组长（要抽检、要证据、要横向可比）、开发与维护者（要能跨宿主运行、能持续演进）。

按用户任务（JTBD）拆开看，更能说明优化的落点：

| 用户任务 | 现状阻碍 | 对应需求 |
|---|---|---|
| 当我要交下周教案时，我想按周次课次直接拿到合规初稿，以便把时间留给学情分析 | 套别硬编码，周次课次与课题没有一致性校验 | FR-01、FR-14 |
| 当教研组抽检时，我想一键拿出结构与审校证据，以便说明这节课为什么这样设计 | 报告没有教案快照，同哈希可反复通过，角色模拟也能开门禁 | FR-03、FR-05、FR-06 |
| 当我要改动某一环节时，我想立刻知道旧审查是否失效，以便不带过期证据导出 | 失效是哈希的隐式副作用，没有任何提示 | FR-16 |
| 当我把成品交给教研组时，我想拿到一份信息完整、可打印的 Word，以便直接归档 | 学校、编号、授课日期丢失，课时显示 `2.0`，缺图静默消失 | FR-02、FR-10 |
| 当我换到另一个 IDE 或飞书时，我想同一套技能照样能用，以便不被单一平台绑定 | `python` 命令与中文编码问题会让 hook、MCP 直接断掉 | FR-07、FR-08、FR-17 |

### 2.2 教师使用旅程与断点

| 阶段 | 教师动作 | 系统现状 | 主要断点 |
|---|---|---|---|
| 提需求 | 说周次、课次、课题 | 技能规则要求缺输入先问 | 无"周次课次—课题—套别"一致性规则，写错也不报 |
| 起草 | 生成或修订 JSON | `draft.py` 可出完整骨架 | 套别硬编码为第 21、22 套，与样例目录冲突 |
| 结构校验 | 跑 `validate.py` | 字段、八步、必须完成可检 | 结构化写法绕过"必须完成"；课时与活动分钟不校验 |
| 对抗审校 | 独立审校提反例 | 单反例、哈希绑定、可放行 | 报告不存被审教案，旧报告无法复核；同哈希可反复"通过" |
| 导出 | 生成 DOCX | 结构 + 审查双门禁 | Word 缺学校、编号、授课日期；课时显示 `2.0`；缺图静默丢 |
| 归档复用 | 下次接着改 | 同名文件直接覆盖 | 无版本号、无历史、无法对比 |
| 跨宿主 | 换 IDE 或飞书 | 同一技能目录复用 | `python` 命令、UTF-8 输出、MCP 异常三处易断 |

### 2.3 教研组与质量治理视角

教研组真正需要的是"出了问题能查到当时依据"。当前报告只保存 `planHash`，不保存被审教案内容，报告一旦与教案同时改动就无法还原；现网 `第1周第1次*.review.json` 中第 1—3 轮哈希完全相同、第 9—10 轮哈希也完全相同且全部 `passed`，说明重复审校没有被识别，证据链存在"盖章"风险。放行记录可以重复追加，也没有与任课教师身份绑定，抽检时难以判断"谁在什么时候基于什么放行"。

### 2.5 问题归因

五类根因，对应后文的优化主线：

1. **规则不闭合**：校标要求写在文档里，但校验器只覆盖了一部分表达形式，换一种写法就绕过（D-01、D-02、D-16）。
2. **状态机不一致**：审查状态、问题状态、放行记录三者可以各自成立，门禁只看其中一部分（D-03、D-04）。
3. **证据不可复核**：报告与教案只靠哈希关联，缺快照、缺轮次约束、缺独立性标记（D-05、D-06）。
4. **运行时脆弱**：编码、命令、参数异常三处都会让自动化路径整体失效（D-07、D-08、D-09、D-10、D-17）。
5. **资产与度量失真**：样例库没有同步、评分没有区分度、导出产物缺元信息（D-11、D-12、D-14、D-15）。

## 3 优化目标与优先级

### 3.1 优化目标

| 目标 | 对应研究问题 | 基线（2026-10-25） | 目标值 |
|---|---|---|---|
| G1 规则不漏检 | RQ1 隐性规范如何转成可检规则 | 已复现 3 类可绕过写法（D-01、D-02） | 已知违规样本检出率 100%；结构合规率 ≥95% |
| G2 生成与验收真正分离 | RQ2 证据不可复用、责任可落地 | 门禁误放行 ≥1 例（D-03）；证据链完整率 0（无快照） | 误放行 0；证据链完整率 100% |
| G3 跨宿主稳定 | RQ3 文件型插件在真实环境能否稳定 | MCP、Hook 各 1 类必崩；跨宿主无冒烟记录 | 崩溃率 0；跨宿主一致率 ≥95% |
| G4 教师愿意用 | 产品可用性 | 单份耗时未实测；导出一次成功率未测 | 单份耗时较人工下降 ≥30%；一次成功率 ≥90% |

基线一列只写已经有证据的值；标"未测"的项本身就是第一批测量任务，不当作已知结论使用。

**与通用方案的差异**：通用 AI 写作工具能写出像教案的文字，但没有校标字段约束、没有导出闸门、没有可复核的审查证据；纯提示词方案能把格式要求写得更细，却无法阻止模型漏项或换一种写法绕过。本方案的差异不在"生成"，而在**验收可执行、证据可复核、宿主可迁移**——本轮 18 条需求正是把这三件事补成可测项。

### 3.2 优先级定义

- **P0（必须先做）**：影响门禁正确性、证据链成立或自动化路径可用，不修则"合规"结论不可信。
- **P1（本轮应做）**：影响教师日常可用性、评审可检查性或论文指标有效性。
- **P2（可排后）**：效率增强、体验优化，不影响结论成立。

## 4 功能优化需求详述

### 4.1 P0 需求

#### FR-01 校标结构规则补全

**对应问题** D-01、D-02　**优先级** P0

**现状**：`validate_plan` 在 `taskImplementation` 为结构化活动时把任务文本置空，`必须完成/必做` 规则不生效；活动 `minutes` 只校验非负，不校验与 `plannedHours` 的合计关系；缺字段时同一路径产生两条 issue；`isinstance(week, int)` 放行布尔值；没有周次课次与课题、套别的一致规则，而开题报告把它列为三大格式风险之一。

**目标行为**：校标规则对字符串与结构化两种写法一视同仁；活动分钟合计与 `plannedHours × 45` 的偏差在可配置容差内；周次课次、课题、套别三者按目录映射校验，冲突时按严格模式拒绝；issue 去重、排序并带严重度；类型判定排除布尔；校验结果增加 `warnings` 与 `ruleVersion`。

**验收标准**

**对应问题** D-16　**优先级** P2

**现状**：`draft_plan` 用 `第21套/第22套` 和 `第1套/第2套` 硬编码，与 CATALOG 的第 3、4 套冲突；`draft_plan` 已支持 `must_do`、`optional`、`student_context`，但 `draft.py` 没有暴露这些参数。

**目标行为**：套别由样例或配置决定，移除硬编码；CLI 暴露 `--must-do`、`--optional`、`--student-context`、`--plan-number`、`--teach-date`；无匹配样例时输出警告并说明使用的默认值。

**验收标准**
- `draft.py --week 2 --session 1 --title 一级考证辅导2` 输出第 3、4 套。
- 新增参数全部生效并写入 JSON。
- 无匹配时给出明确警告。

**功能测试要点**
- 1—18 周课次组合；跨课程标题；空标题。

**影响文件**：`lib.py`、`draft.py`、README、测试。

#### FR-15 Stop 门禁化与范围修正

**对应问题** D-17　**优先级** P2

**现状**：Stop hook 只扫描当前目录下三类 glob、最多 8 份，审查缺失只写备注不阻断；教案放在子目录时不会被发现。

**目标行为**：递归扫描可配置根目录，跳过 `node_modules`、`output` 等噪声目录；审查缺失或报告过期按 `warn/fail` 可配（默认提示，严格模式失败）；汇总输出所有教案的校验与门禁结论。

**验收标准**
- 子目录中的教案能被发现并检查。
- 严格模式下审查缺失返回非 0；宽松模式仅提示。
- 超过 8 份时全部检查，性能可接受。

**功能测试要点**
- 大目录、符号链接、无权限目录、混合文件类型。

**影响文件**：`hook-stop.py`、`hooks.json`、hooks 测试。

#### FR-16 一键流程与字段级修订

**现状**：技能要求手工执行"读字段表 → 对照样例 → 填 JSON → 校验 → 审校 → 导出"五步；修订某一节要改 JSON 再重跑校验与审校，旧报告失效是哈希的隐式副作用，教师看不到提示。

**目标行为**：提供一键流程命令，串起草稿、校验、审校、导出，可断点执行；提供字段级修订命令（按路径设置值），输出变更摘要并显式提示"旧审查报告已失效"；提供两版教案差异输出。

**验收标准**
- 一条命令产出可通过门禁的 docx 与审查报告。
- 修订命令执行后提示报告失效，重新审校后恢复。
- 非法字段路径被拒绝且不修改原文件。

**功能测试要点**
- 断点：在校验失败、审校不通过、导出失败三处中断后的状态。
- 原子性：修订失败不破坏原文件。

**影响文件**：新增流程与修订脚本、`SKILL.md`、`commands/`。

#### FR-17 安装自检与清单一致性

**现状**：插件依赖 Python、LibreOffice、Playwright 与 5 份宿主清单，但没有任何自检；5 份 `plugin.json`、两份 MCP 配置与安装文档的命令写法已经不一致。

**目标行为**：提供 `doctor` 自检命令，检查 Python 版本与可用命令、LibreOffice、Playwright、`PLUGIN_ROOT`、5 份清单字段、样例可校验性；输出可执行的修复建议；不一致项列为失败。

**验收标准**
- 缺 Playwright、无 soffice、清单字段不一致三类环境均给出明确提示。
- 自检结果可被 CI 调用并以退出码表达。

**功能测试要点**
- 各类缺失组合；路径含中文。

**影响文件**：新增自检脚本、`docs/`、README。

## 9 假设与待确认事项

1. 8 份 C 语言教案的 95 分钟按"修订为 90 分钟"处理，而不是放宽容差；若教研组认为应保留 95 分钟，则改为允许 ±10% 容差。
2. 严格模式（教师必填、要求独立子代理审校）默认关闭，仅作为可配置项，避免破坏现有 5 类宿主用法。
3. 评分阈值沿用开题的 85 分；区分度新增判据"金标准与弱教案分差 ≥15"。
4. 本说明书只定义目标行为与验收口径，具体实现方案在技术设计阶段确定。
5. 现有报告与历史产物不做破坏性清理，只做兼容读取与标注。
