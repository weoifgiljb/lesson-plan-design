# 前端代码规范

> 状态：v1.0（2026-11-04），适用于 `src/frontend/**`。
> 规则等级：**必须（MUST）** / **应当（SHOULD）** / **可以（MAY）**。
> 优先级：`AGENTS.md` 与本规范优先；Vue 官方风格指南作为默认基线，冲突时以本仓库规则为准。
> 落地检查：`cd src/frontend && npm run check`（typecheck + lint + vitest）。

这份规范解决三个问题：

1. 新页面/组件应该放在哪、依赖谁、不能依赖谁；
2. 哪些写法会留下维护债，评审时怎么一眼看出来；
3. 哪些规则已经由工具强制，哪些仍需人工评审。

---

## 0. 适用范围与例外

适用于 `src/frontend` 下的 Vue 组件、TypeScript、样式、测试与构建配置。

**明确例外**（不按普通源码要求，但仍需保持可复现）：

| 例外 | 原因 | 约束 |
|---|---|---|
| `src/api/types.gen.ts` | 由 `scripts/gen_frontend_types.py` 生成 | 禁止手改；契约变更时重跑脚本 |
| `src/dev/**` | 只服务开发/演示的 fixture | 不得被生产路由引用；不得含真实学生信息 |
| `src/styles/element.css` | Element Plus 主题映射层 | 只允许在这里覆盖 Element 变量与内部结构 |
| `src/styles/tokens.css`、`src/styles/palette.ts` | 设计令牌的单一事实源 | 允许出现具体色值；两处必须逐值一致，由 `tokens.spec.ts` 锁定 |

**机器强制 vs 人工评审**：

| 规则 | 强制方式 |
|---|---|
| 类型、未使用变量、`any`、Vue 组件 API | `vue-tsc` + ESLint |
| 网络出口、`v-html`、调试日志 | ESLint |
| 目录分层、组件体量、命名语义、四态完整性、令牌使用 | 评审 + PR 清单 |
| 契约/类型同步 | `run_backend_gate.py` + `gen_frontend_types.py` |

## 1. 技术栈与单一事实源

| 关注点 | 唯一来源 | 说明 |
|---|---|---|
| 接口契约 | `docs/api/contract.v1.json` | 双端契约基线；字段、错误码、状态以它为准 |
| 前端契约类型 | `src/frontend/src/api/types.gen.ts` | 由 `scripts/gen_frontend_types.py` 生成，首行带 OpenAPI 快照哈希 |
| 手写前端模型 | `src/frontend/src/api/models.ts` | 放前端共享/派生模型；契约已有的类型优先用 `types.gen.ts`，不重复定义 |
| 错误码与兜底文案 | `src/frontend/src/api/errors.ts` | 集合必须与后端 `ERROR_CODES`、契约一致 |
| 网络出口 | `src/frontend/src/api/client.ts` | 全站唯一 `axios` 实例；CSRF、超时、响应解包都在这里 |
| 设计令牌 | `src/frontend/src/styles/tokens.css` + `palette.ts` | CSS 用变量，JS/TS 用 `PALETTE`/`CHART_TOKENS`；`tokens.spec.ts` 锁定一致性 |
| 状态文案 | `src/frontend/src/utils/labels.ts` | 审查/任务/导出状态的中文名只在这里定义 |
| 前端门禁 | `src/frontend/package.json` 的 `check` | `typecheck → lint → test`，提交前必须全绿 |

**必须**：

- 契约变更时，`contract.v1.json`、`openapi.v1.json`、`types.gen.ts`、前端调用与测试同批提交。
- 前端不自己发明状态、错误码、枚举值；需要新值时先改契约与后端。
- 不在页面里手写后端已经下发的枚举/限制；优先用 `/meta` 或 `labels.ts`。

## 2. 目录分层与依赖方向

```text
src/frontend/src/
  api/          端点函数、请求/响应模型、错误映射；唯一网络出口
  components/   可复用展示/业务组件；按领域分子目录（overview/stats/structure/tasks/...）
  composables/  组合式函数：取数、分页、派生逻辑
  dev/          仅开发/演示的 fixture；不得进入生产路由
  layouts/      应用外壳（AppShell）
  router/       路由表、守卫
  stores/       Pinia：目前只有 session
  styles/       设计令牌、全局基础样式、Element Plus 覆盖
  utils/        纯函数：日期、颜色、文案、教案内容/结构派生
  views/        页面级组件：编排布局、取数、四态与交互
```

**依赖只能向下，不能反向**：

| 层 | 允许依赖 | 禁止依赖 |
|---|---|---|
| `views` | `components`、`composables`、`api`、`stores`、`router`、`utils`、`styles` | 其他 `views` 的内部实现 |
| `components` | `components`、`composables`、`utils`、`api`（只读数据）、`styles` | `views`、`router` 的页面级逻辑 |
| `composables` | `api`、`utils`、`vue` | `views`、`components`（避免循环） |
| `api` | `client`、`client-error`、`models`、`types.gen` | `views`、`components`、`stores`、`router` |
| `stores` | `api`、`models` | `views`、`components` |
| `utils` | 纯 TS/浏览器 API | `vue`、`api`、`components`、`views`、`stores` |
| `styles` | 无 import | 任何 JS/TS |

补充约定：

- 展示组件优先通过 props/emits 通信，不直接 import store；只有 `layouts/AppShell.vue`、路由守卫等会话感知位置可以读 `session`。
- 同一行为出现 3 次以上再抽 composable/组件；两行以内的包装不算重复。
- **体量建议**：单个 `.vue` 建议 ≤ 500 行（含样式），`<style>` 建议 ≤ 150 行；单函数 ≤ 50 行、嵌套 ≤ 3 层；单组件 props 建议 ≤ 10 个。超过时在 PR 说明并优先拆分，而不是继续堆叠。
- 构建产物 `dist/`、`coverage/` 不入库；`node_modules/` 已在根 `.gitignore`。

## 3. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 组件文件/组件名 | PascalCase，多词；根组件 `App` 例外 | `PlanDetailView.vue`、`StatsLedger.vue` |
| 紧耦合子组件 | 以父组件名为前缀 | `TaskQuadrantBoard.vue`、`OverviewBoard.vue` |
| composable | `use` + 名词/动词 | `useApiRequest`、`usePagedQuery` |
| store | `use` + 领域 + `Store` | `useSessionStore` |
| API 函数 | 动词 + 资源 | `listPlans`、`getPlan`、`createExports`、`downloadExport` |
| 类型/接口 | PascalCase，不加 `I` 前缀 | `PlanDetail`、`Paged<T>`、`ReviewStatus` |
| 常量/映射表 | UPPER_SNAKE | `ERROR_MESSAGES`、`REVIEW_STATUS_LABELS` |
| CSS 类 | kebab-case，BEM 风格 | `.state-panel`、`.state-panel__title`、`.metric-ledger--compact` |
| props | camelCase | `planVersionId`、`showActions` |
| emits | 模板中用 kebab-case，声明用 camelCase | `@update:page` / `update:page` |
| 测试文件 | 与源文件同目录，`<name>.spec.ts` | `ExportsView.spec.ts` |
| 开发 fixture | 只放 `src/dev/`，命名 `DEMO_*` | `DEMO_PLANS`、`DEMO_STRUCTURE` |

**必须**：

- 组件名用完整单词，不用难以理解的缩写（`API`、`ID`、`URL` 等通用缩写除外）。
- 不用 `data1`、`list2`、`temp`、`obj` 这类无语义命名。
- 事件名表达“发生了什么”，不表达“怎么处理”：`saved`、`changed`，而不是 `handleSaveClick`。

## 4. Vue 单文件组件（SFC）

### 4.1 结构

```vue
<script setup lang="ts">
// 1. 类型 import
// 2. 值 import
// 3. props / emits
// 4. 局部状态
// 5. computed / watch
// 6. 方法
</script>

<template>
  <!-- 模板只做展示与轻量条件 -->
</template>

<style scoped>
/* 只使用 --lpp-* 令牌 */
</style>
```

**必须**：

- 只用 `<script setup lang="ts">`；禁止 Options API（`export default { data() {} }`）。
- 块顺序固定为 `script → template → style`；样式默认 `scoped`。
- props 用类型声明 + `withDefaults`；emits 用类型声明。
- `v-for` 必须有 `:key`，优先使用稳定业务 id；禁止用数组下标作为 key，除非列表完全静态且注释说明。
- 禁止在同一元素上同时使用 `v-if` 与 `v-for`；先过滤成 computed，或把 `v-if` 移到容器。
- 模板中只放简单表达式；复杂判断/格式化放到 computed 或函数。
- 不在模板中发起请求；请求在 `onMounted`/事件处理器/`useApiRequest` 中完成。
- computed 必须是纯函数，不修改状态、不发请求、不操作 DOM。
- `watch` 必须写清来源和副作用；组件卸载时清理定时器、事件监听、`ResizeObserver`、ECharts 实例。
- `v-html` 只允许出现在 `MarkdownView.vue`，且内容必须经 DOMPurify 清洗；保留带原因的 `eslint-disable` 注释。
- 不直接修改 props；需要变更时 emit 给父组件。
- `defineExpose` 只在父组件确实需要通过 ref 调用时使用；优先 props/emits。

### 4.2 组件 API

- props 名称用 camelCase；模板中统一 PascalCase 组件标签，Element Plus 用 kebab-case（如 `<el-button>`）。
- 事件声明用 `defineEmits<{ saved: [id: number]; cancel: [] }>()` 这类类型形式。
- 插槽命名用 kebab-case；默认插槽不命名。
- 组件不隐式依赖父级 DOM 或全局变量；需要的能力通过 props/emits/composable 注入。
- 同一组件只承担一个视觉/业务职责；表格、筛选、分页、弹窗等可组合能力优先拆成子组件或 composable。

## 5. TypeScript

**必须**：

- 保持 `strict: true`；不新增 `any`。不确定类型用 `unknown`，再用类型守卫/收窄。
- 只用作类型的 import 使用 `import type`。
- 封闭集合用字符串联合 + 映射表，不写裸字符串分支：

```ts
export type ReviewStatus =
  | 'structure_invalid'
  | 'pending_reviewer'
  | 'needs_repair'
  | 'passed'
  | 'passed_with_override'
  | 'passed_with_accepted_minor'

export const REVIEW_STATUS_LABELS: Record<ReviewStatus, string> = {
  structure_invalid: '结构失败',
  pending_reviewer: '待审',
  needs_repair: '待修复',
  passed: '通过',
  passed_with_override: '放行通过',
  passed_with_accepted_minor: '接受轻微',
}
```

- 不使用 `@ts-ignore`；确需压制时用 `@ts-expect-error` 并写原因。
- 非空断言 `!` 只允许在测试中或已由前置判断保证的位置；优先可选链和显式收窄。
- 类型断言 `as` 需要注释理由；禁止双重断言 `as unknown as T` 绕过类型系统。
- 导出的函数写返回类型；内部短函数可依赖推断。
- `catch` 参数按 `unknown` 处理；错误统一转成 `RequestError` 或 `toApiError()` 的结果。
- 不手改 `types.gen.ts`；契约变化后运行 `py -3 scripts/gen_frontend_types.py`。
- 不用 `enum`、`namespace`；用联合类型、常量对象和 ES module。

**应当**：

- 对象形状优先 `interface`，联合/工具类型用 `type`。
- 需要“穷举检查”时用 `satisfies` 或 `Record<Union, T>`，让新增成员编译期报错。
- 类型放近使用处；跨页面共享的放 `api/models.ts` 或对应领域的 `types.ts`。

## 6. API、契约与数据流

**必须**：

- 只有 `src/frontend/src/api/client.ts` 可以 `import axios`；其他文件禁止直接使用 `fetch`、`XMLHttpRequest`、裸 WebSocket。
- `src/frontend/src/api/*.ts` 每个端点一个函数，返回 `models.ts`/`types.gen.ts` 中的类型；不在 API 模块里写 UI 逻辑。
- 页面取数统一走 `useApiRequest`；列表分页统一走 `usePagedQuery`。不要在每个页面复制 loading/error/401/403 处理。
- 错误展示统一用 `errorMessage(code, serverMessage)`；错误态展示 `code` 与 `traceId`，不展示堆栈。
- 查询参数用对象传给 `client.get(path, params)`；不要手拼 `?a=1&b=2`。
- 筛选变化/翻页时保留请求序号保护，防止旧响应覆盖新筛选（`useApiRequest` 已实现）。
- 契约变更同批：`contract.v1.json`、`openapi.v1.json`、`types.gen.ts`、前端调用、测试。改到 `src/frontend/src/api` 或 `docs/api` 时按 AGENTS #17 跑后端闸门。
- 认证走 httpOnly Cookie + CSRF（`client.ts` 读取 `lpp_csrf`）；不把 token 写入 `localStorage`/`sessionStorage`，不放进 URL。

**推荐数据流**：

```text
页面 mounted / 筛选变化
  → useApiRequest / usePagedQuery
    → api/xxx.ts
      → api/client.ts
        → 后端 /api/v1/...
  → 页面四态（loading / empty / error / forbidden）
  → 子组件只接收已整理好的 props
```

- 页面是“编排层”，负责取数、四态、把数据拆成子组件需要的形状。
- 子组件不直接取数；需要交互时 emit，由页面决定是否重新请求。
- 全局只放会话；筛选、分页、弹窗开关等放页面局部状态。

## 7. 状态、四态与会话

**必须**：

- 每个页面/数据区块处理四种状态：`loading`、`empty`、`error`、`forbidden`；统一使用 `src/components/StatePanel.vue`。
- `error` 态展示 `code` 与 `traceId`，并提供重试；不显示半截数据或空表格冒充成功。
- `empty` 态说明“为什么空”和“下一步做什么”，不能只显示空白。
- 401 统一跳登录并带 `redirect`；403 跳 `/403`；`PASSWORD_CHANGE_REQUIRED` 跳改密页。
- 全局状态只放 Pinia `useSessionStore`；页面状态用 `ref`/`reactive`，不要塞进 store。
- 认证态只存在内存 store；刷新通过 `fetchMe()` 重新获取，不持久化 token。

**应当**：

- 可分享的筛选条件放 URL query（如 `?status=needs_repair&page=2`），刷新/复制链接可复现。
- 变更操作成功后以服务端返回为准重新取数；不做未经确认的乐观更新。
- 危险操作二次确认；确认文案说明影响范围。

## 8. 样式、设计令牌与响应式

### 8.1 令牌

**必须**：

- 组件/页面样式只使用 `--lpp-*` 变量；禁止新增裸十六进制、`rgb()`、`rgba()` 色值。
- JS/TS 中需要颜色时使用 `src/styles/palette.ts` 的 `PALETTE`/`CHART_TOKENS`，不要在每个组件里 `getComputedStyle`。
- 新增令牌必须同步 `tokens.css` + `palette.ts` + `tokens.spec.ts`；缺一不可。
- 允许出现具体色值的只有：`tokens.css`、`palette.ts`、`element.css`（Element Plus 映射层）、`BrandMark.vue` 的品牌 SVG（需注释）。
- 间距走 4px 体系（`--lpp-space-*`）；字号、行高、圆角、阴影只用现有令牌。圆角只有四档：4 / 6 / 10 / 14。
- 单一浅色主题；不新增暗色主题、不引入主题切换持久化。

### 8.2 作用域与覆盖

**必须**：

- 组件样式默认 `scoped`；全局样式只放 `styles/base.css` 与 `styles/element.css`。
- Element Plus 的变量与内部结构覆盖只在 `styles/element.css`；页面/组件不直接改 Element 内部类名。
- 不使用 `!important`；唯一例外是 `base.css` 中 `prefers-reduced-motion` 的强制降级，以及有注释说明的 canvas 尺寸约束。
- 类名用 BEM/kebab-case；避免 `.btn`、`.card` 这类通用类名。
- 避免深层选择器；覆盖 Element Plus 时优先用 `:deep()` 并限定在组件根类下。

### 8.3 响应式

**必须**：

- 统一使用 `max-width` 断点：`1180px`（布局压缩/双列降级）、`900px`（平板）、`767px`（移动/导航收起）。`480px` 仅用于登录/注册等极窄场景，新增时在 PR 说明。
- 新断点不得随意增加；确实需要时先更新本规范与相关组件。
- 页面至少自查 1440、1280、390 三档；表格在窄屏要么转卡片，要么横向滚动并给出提示。
- 动效尊重 `prefers-reduced-motion`；不要做无限循环的装饰动画。

## 9. 可访问性（A11y）

**必须**：

- 使用语义标签：导航用 `nav`，主内容用 `main`，标题按层级 `h1 → h2 → h3`。
- 可点击元素用 `button`/`a`，不用 `div @click`；图标按钮必须有 `aria-label`。
- 装饰性图标/SVG 加 `aria-hidden="true"`；有意义的图片写 `alt`。
- 表单字段有 `label`；错误提示通过 `aria-describedby` 关联到字段。
- 键盘可达：Tab 顺序合理、焦点环可见、Esc 可关弹窗、焦点在关闭后回到触发元素。
- 文字对比度 ≥ 4.5:1；状态不能只靠颜色区分，必须同时有文字/图标。
- 图表提供 `aria-label` 与文本摘要；表格有表头；空态/错误态可被读屏感知。
- 不劫持浏览器默认行为（滚动、缩放、右键）除非有明确业务理由。

**应当**：

- 用 `role="status"`/`role="alert"` 标注加载与错误消息。
- 复杂交互（命令面板、拖拽看板）提供键盘替代路径；做不到时在 PR 说明限制。

## 10. 测试

**必须**：

- 使用 Vitest + `@vue/test-utils`；spec 与源文件同目录，命名 `<name>.spec.ts`。
- 纯函数（`utils/`、`composables/`、`components/*/model.ts`）优先直接单测，不需要挂载 DOM。
- 组件测试测行为：渲染文本、触发事件、断言 emit/props、断言四态；不断言内部实现细节。
- mock 只放在 API 边界（`vi.mock('@/api/...')`）；不 mock 被测组件自己的内部函数。
- 页面测试至少覆盖：正常渲染、loading、empty、error（含 code/traceId）、关键交互/权限分支中的相关项。
- 新功能必须带 spec；修 bug 先补一个能复现的失败用例。
- 测试不依赖真实后端、真实网络、真实时间；必要时用 fake timers。
- 测试数据不含真实学生信息；fixture 放 `src/dev/` 或 spec 内。

**应当**：

- 测试名描述行为，不写“test1”“works”。
- 不写大段 DOM snapshot；需要结构断言时用小范围、可读的断言。
- 覆盖率作为参考，不作为唯一目标；关键路径必须有正常/边界/错误用例。

## 11. 性能与安全

### 11.1 性能

**必须**：

- 路由页面使用动态 `import()`；首屏不引入 ECharts/three 等重库。
- 大列表分页或虚拟化；不在模板里对全量数据做重型计算。
- 新增依赖前评估体积、许可和维护状态；在 PR 说明理由。
- 不提交 `dist/`、`coverage/`、构建缓存。

**应当**：

- ECharts 按需注册（`echarts/core` + 所需 chart/component），或把图表组件异步加载。
- three.js 只在 `src/components/structure/` 内使用；其他页面不直接 import。
- 图片/字体使用本地资源；不请求外部字体。

### 11.2 安全

**必须**：

- `v-html` 只允许经 DOMPurify 清洗的 Markdown；其他场景禁止。
- 禁止 `eval`、`new Function`、动态 `script` 注入。
- 不在前端代码、日志、URL、Web Storage 中放 token、密码、学号等敏感信息。
- 外链使用 `rel="noopener noreferrer"`。
- 上传类型/大小在前端提示，但后端仍必须校验；前端提示不能代替后端限制。
- 错误提示不泄露堆栈、SQL、文件路径。

## 12. 提交、评审与门禁

### 12.1 分支与提交

| 类型 | 分支格式 | 示例 |
|---|---|---|
| 功能 | `feature/fe-<id>-<slug>` | `feature/fe-02b-task-board` |
| 修复 | `fix/fe-<id>-<slug>` | `fix/fe-01-simple-structure` |
| 重构 | `refactor/<slug>` | `refactor/fe-code-style` |
| 文档 | `docs/<slug>` | `docs/frontend-code-standards` |

提交信息：`<type>(<id>): <摘要>`；`type` 取 `feat`、`fix`、`docs`、`test`、`refactor`、`chore`。一次提交只做一件事；重构不夹带新功能。

### 12.2 PR 必填

- 关联需求/缺陷编号与测试用例编号。
- 改了什么、没改什么、如何验证、风险。
- 前端部分填写 `.github/pull_request_template.md` 的“前端”清单。
- UI 改动附 1440/1280/390 截图，或 `frontend-style-review` 报告。
- 契约/类型变化附 `run_backend_gate.py` 结果与 `types.gen.ts` 快照更新。

### 12.3 门禁

```bash
cd src/frontend
npm run check      # typecheck + lint + vitest

# 仅当改动 src/backend、src/frontend/src/api 或 docs/api 时
py -3 scripts/run_backend_gate.py
py -3 scripts/gen_frontend_types.py
```

- `npm run check` 不通过不得合并。
- `lint` 目标为零 warning（见 `refactor/fe-code-style` 落地后的 `--max-warnings 0`）。
- 后端闸门未通过、或评审结论为“拒绝”时不得合并。
